# 电竞 UI 与导播控制系统实施规格

目标：在已有单文件 HOOK / C++ 接收链路上完成可运行的多导播系统，包含主服务鉴权与订阅、导播本地服务、控制页和 OBS 输出页。用户已确认采用中文深色电竞风，且每个功能都保留独立开关。本规格用于逐项验收，不以静态界面或模拟数据演示代替完成。

## 结构与数据边界

- DCS 任务环境负责 1 Hz 采样与即时事件预编码，HOOK 负责注入和有界传输。导播数量不增加 DCS 采样次数。
- C++ 主服务器继续作为事件与状态的权威内存仓库，增加登录、角色、源授权、WebSocket 订阅和恢复游标。
- 每台导播电脑运行独立本地 Web 服务。服务持有主服务器会话；浏览器控制页和输出页均只访问本地服务。一个服务可管理多个输出，也可在不同端口运行多个互不影响的服务。
- 控制服务持久保存画面配置；账号密码不落盘，主服务会话不传给输出页。事件传输继续使用明确的 memory ACK，不增加文件转发链路。
- 默认主服务、本地服务绑定回环。异机主服务连接使用 HTTPS/WSS，证书必须验证；不通过关闭 TLS 校验实现部署。

## 转播视觉规范（2026-10-17 修订）

按用户确认的 CS 赛事直播 HUD 重做 OBS 输出：中央留空给游戏，蓝、红双方选手卡分别贴左右边缘，顶部是队名、比分、任务时间。小地图在左上，事件在右上，导弹摘要在底部。控制台负责设置，不能把控制台的面板布局当成转播输出。

- 默认透明背景，游戏图像由 OBS 下层游戏捕获提供；输出自身不采集 DCS 视频。
- 名字优先使用真实玩家名；AI 显示单位呼号及 AI 标识。机型使用采集值，不生成虚构头像、生命值或经济数据。
- 血量条替换为油量条。按 DCS 内部油箱容量基准显示百分比，超过 100% 不截断数值；条形上限 100%。未知为破折号和纹理条，低于 20% 使用警示色，旧值有标记。
- 标准阵容每侧 5 张卡、紧凑阵容每侧 8 张卡，每 12 秒轮换；手动焦点对象优先显示，其余对象完整分页，不漏掉分页末尾选手。各侧显示总数与页码，不把采集架数称为存活人数。
- 两种布局都留出中央游戏区域；大安全边距整体缩小 HUD，避免小地图与选手卡重叠。
- 提供十六项组件与数据开关。关闭选手数据项影响两侧标牌；速度开关也影响导弹速度文字。按输出独立保存。

## 默认画面与功能开关

默认预置「比赛直播」「紧凑阵容」两个独立输出，支持创建、重命名、复制与删除。每个输出独立选择数据源、布局、对象、过滤条件和组件开关，保存后服务重启可恢复。

| 功能 | 展示内容 | 控制项 |
| --- | --- | --- |
| 比赛信息 | 赛事名、队名、手动比分、任务时间 | 显示开关，文字与比分编辑；不猜测胜负规则 |
| 战术小地图 | 飞机位置、阵营、航向、选中对象、导弹与目标关系 | 显示开关、自动适配视野、阵营过滤、对象标签、导弹连线 |
| 两侧选手卡 | 飞机类型、玩家/AI、当前采集状态、速度、燃油、武器 | 显示开关、阵营、仅玩家、排序与搜索 |
| 导弹追踪 | 弹型、发射者、当前观察目标、最后已知目标、速度 | 显示开关、选择导弹、跟随焦点飞机、连线开关 |
| 事件播报 | 发射、命中、击杀、损失、起降等已收到事实 | 显示开关、类型过滤、条数与停留时间；重连不重复弹出已播报事件 |
| 链路状态 | 在线/过期/暂停/结束、未知值、传输与采集缺失提示 | 输出状态条开关；控制台始终显示真实健康状态 |

输出提供 1920×1080 自适应设计、透明背景选项、布局预置和安全边距。输出是只读页面，复制其地址即可用于 OBS 浏览器源。实际数据缺失时显示等待/未知/过期，不能将空值渲染为零油量、零速度或不存在目标。

所有功能开关属于 outputId 的配置，不使用浏览器全局状态共享输出设置。更新带 revision，冲突返回明确提示，防止两个控制页互相覆盖。控制页提供实时预览及 OBS 地址复制。

## 登录、权限与连接

- 账号由管理员配置，不开放注册。角色为 admin、director、viewer；HOOK 上传凭据保持独立。
- 密码使用成熟密码学实现的带随机盐派生，设置登录限速；会话有过期、注销和撤销机制。重密码计算不能阻塞接收事件循环。
- director 管理自己本地服务内的输出并订阅授权源，viewer 只读，admin 管理账号及源权限。服务端检查权限，不依赖隐藏按钮。
- 本地控制接口校验 Host、Origin、会话和写操作 CSRF。输出凭据仅具备单画面的只读权限，不能调用配置写接口或读取主服务会话。
- 重连按源与 serverEpoch 恢复事件游标，旧任务数据不能覆盖新任务。服务重启/保留窗口不足时明确标记需要重建基线；慢客户端不会影响 HOOK ACK。
- UI 根据主服务的在线与数据年龄显示新鲜度，暂停与断线分开。captureIntegrity、transportComplete、historyRetained 分别显示，不能把服务器收齐解读为采集无缺失。

## 0.5.0：选手池与手动队伍

输出配置增加 `competition`、`nameplates`、`docks`。这些设置由本地导播持久化，每个输出独立，不更改任务采集频率。控制台草稿预览与 OBS 发布配置分开，保存后广播；十二项组件总开关仍实时保存。队标为经过浏览器压缩的内嵌位图，不引入外部图片服务。

选手池通过玩家名称映射任务实体，飞机生命周期 ID 继续来自采集器。阵营模式按飞机 coalition 自动分组；队伍模式只依据手动池归属分组，两个模式共用名单与绑定，队伍模式不再以 DCS coalition 过滤阵容。比分纯人工维护。

死亡判断分两类证据：任务事件中的物理死亡事实，以及 Hook 的网络断线回调。后者由新嵌入模块 `players.lua` 采集，每秒随 status 发送，C++ 保持透传；不把 mission 的 player_left 当作断线，不把整条数据链路离线当作全部玩家死亡。导播在任务源内保存紧凑飞机/死亡记录，供多个输出共享事实。配置和位置独立，事实不按输出复制。

Dock 支持组件、单张标牌、固定飞机席位、自动跟随选手的席位及独立队标。默认布局保留中心区域；用户自定义位置可以主动覆盖任意区域。具体字段和边界见浏览器协议及导播使用说明。


## 0.8.0 移除状态栏及特写

状态栏读取/控制和 F2 自动跟随已从 HOOK、控制 API 及 UI 删除，底部特写不再渲染。旧特写配置保留身份并迁移到比赛直播；1 Hz 采集、事件 ACK 和选手池不变。
